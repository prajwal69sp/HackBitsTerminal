# Hack Bits Terminal — starter v0.1.0

An Android/Kotlin starter project for the Hack Bits Terminal concept.

## Honest feature status

- **Included:** Android app shell, dark terminal-style UI, Terminal/Linux/Packages tabs, asynchronous command output.
- **Included:** allowlisted demonstration commands run in the app's Android sandbox.
- **Not included yet:** a real PTY terminal, Debian rootfs, PRoot binary, `apt` backend, package installation, VNC/XFCE, root integration.
- **Not a Termux replacement yet.** The Linux and package screens explain the missing backend rather than pretending it exists.

## Build on GitHub Codespaces from Android

1. Create a GitHub repository named `HackBitsTerminal`.
2. Upload this project ZIP's extracted contents to the repository (the root should contain `settings.gradle.kts` and `app/`).
3. Open the repository and choose **Code → Codespaces → Create codespace on main**.
4. In the Codespaces terminal, install/use a supported JDK 17 environment and run:

   ```bash
   java -version
   chmod +x gradlew 2>/dev/null || true
   gradle --version
   gradle assembleDebug
   ```

   If Gradle is not installed, use the Gradle wrapper generated by Android Studio or install Gradle through the official Gradle instructions. A wrapper is preferred for repeatable builds.
5. APK output, if the build succeeds:
   `app/build/outputs/apk/debug/app-debug.apk`
6. Download the APK from the Codespaces file explorer to your phone, inspect it, then install it. Android may ask you to allow installation from the browser/file manager you used.

### Build configuration notes

This starter uses Android Gradle Plugin 8.10.1, Kotlin 2.1.20, compile SDK 35 and min SDK 26. The Codespaces image must have a compatible JDK and Android SDK platform/build-tools. If Gradle reports a missing Android SDK, install Android SDK command-line tools and platform 35 in the Codespace, or use Android Studio's cloud/dev environment setup. Android SDK license acceptance may be required.

For a reliable build, add a Gradle wrapper (`gradle wrapper --gradle-version 8.11.1`) in a compatible Gradle/JDK environment and commit `gradlew`, `gradlew.bat`, and `gradle/wrapper/`.

## How the starter command runner works

`ShellRunner` calls `/system/bin/sh` in the app's sandbox. An explicit allowlist is used. This demonstrates command execution, but it is not a PTY: interactive editors, `top`, `ssh`, job control, and full-screen terminal apps won't work correctly.

## Plan for real Debian integration

A robust implementation needs all of the following:

1. A compatible terminal emulator view and PTY/session layer (review Termux source and licenses before reusing code).
2. An ARM64 PRoot runtime built for Android/bionic or a suitable maintained implementation.
3. A Debian ARM64 root filesystem downloaded from a trusted source over HTTPS, with pinned release metadata and verified SHA-256 checksum/signature.
4. Extraction into private app storage, with path-traversal protections, disk-space checks, cancellation, progress, and rollback on failure.
5. A process supervisor that starts PRoot with correct bind mounts and environment variables.
6. A Linux command adapter that passes arguments safely and handles output, exit status, process termination, and terminal resize.
7. Package actions that invoke `apt` only inside the installed Debian rootfs.
8. Tests on Android 16 / ColorOS and on ARM64. Check scoped storage, process limits, SELinux restrictions, and background execution behavior.

Do not download and execute an arbitrary rootfs or binary without verifying its source and integrity. Do not bundle Kali repositories into Debian as a shortcut.

## Android security notes

- The app has its own Android UID and sandbox. Its shell cannot see or control another app's private files.
- KernelSU on the phone does not automatically grant this app root. Do not add silent root execution.
- Keep Linux data inside app-private storage initially. Avoid broad storage permissions.
- PRoot emulates aspects of filesystem behavior in userspace; it is not a VM and does not provide a separate Linux kernel.
- Raw packet capture, monitor mode, Wi-Fi injection, and some networking features may not work on stock Android kernels or without specific device/kernel support.
- Use scanning and security tools only against systems you own or have permission to test.
